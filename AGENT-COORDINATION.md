## Hard rules

- One shared working copy, `main`. Commit **only your own paths** (`git add <file>...`), never `git add -A` / `git commit -a`. Never `push`, `checkout`, `reset`, `stash`, or `rebase`.
- `npm run build` must be green before you commit.
- Do not touch `package.json` / lockfile except the two granted one-shot changes (pD vitest, then pF playwright). p3 adds the CI steps afterwards.
- Claim a ticket by assigning it before touching files; refer to tickets by name.
- Only the overseer steers other panes. Objections go to the overseer, not to other agents.
- Reviewers never edit source. Their findings go to `.scratch/review-*.md`; the overseer adjudicates and hands changes to the file owner. **Less structure wins, not less code:** fewer entities, screens, deps and abstractions. On UI files craft, warmth and distinctiveness outrank line count; a finding that makes the page plainer is not a win. The tech-debt reviewer covers schema, security and data flow only, never styling or copy. The code-cutter role is retired (founder, 2026-09-03: it was steering toward safe designs).
- Workboard is `docs/PLAN.md`; message board is `D:/projects/MochisLegacy/.scratch/board.md` (append-only, contracts and heads-ups, no directing other panes).
- Sessions are disposable: spawned per task, exited when done. Builders are Grok 4.6 fast (high) or GLM 5.3 flash in pi; reviewers and design judges are **Claude Fable 5.1 at high effort in Claude Code** (from 2026-09-03; Gemini/Muse only finish what they already hold); large judgment calls are the overseer's.
